# tools/ — สคริปต์ตรวจสอบการนับจำนวนแผ่น

สคริปต์รันมือทั้งหมดของโปรเจกต์ — **อ่านอย่างเดียว (SELECT)** ไม่แก้ข้อมูลใน Oracle
(ยกเว้น `seed-fault-zone-map.js` ที่เขียนไฟล์ CSV ลง `../data/` แต่ก็ยังไม่แตะ DB)

ไม่มีตัวไหนถูก `require` จาก `eap-server.js` — ลบโฟลเดอร์นี้ทิ้งเซิร์ฟเวอร์ก็ยังรันได้

> ต้องอยู่บนเครือข่ายบริษัท (wifi **PAIPEI**) ถึงจะต่อ Oracle ได้

---

## วิธีรัน

```bat
cd /d <repo>\backend
node tools\verify-panel-count.js
```

หรือดับเบิลคลิก `tools\run-tools.bat` แล้วเลือกเมนู

ทุกสคริปต์เขียนผลลง `tools/output/*.txt` เป็น **UTF-8** เอง
— **อย่าใช้ `> file.txt`** เพราะ PowerShell จะเขียนเป็น UTF-16 แล้วภาษาไทยเพี้ยน

## สคริปต์

### ตรวจการนับจำนวนแผ่น

| ไฟล์ | ใช้เมื่อไร |
|---|---|
| `verify-panel-count.js` | **ตัวหลัก** — เทียบวิธีนับเดิม (24 ชม.) กับวิธีปัจจุบัน (ต่อ LOT) รายเครื่อง พร้อมติ๊ก ✓ ตัวที่หารด้วย 20 ลงตัว ใส่ชื่อเครื่องต่อท้ายเพื่อดูรายแผ่นที่ถูกตัด/รวม |

| `diagnose-event-types.js` | อยากรู้ว่า `CEID` / `PANELTYPE` มีค่าอะไรบ้าง |
| `diagnose-lot-id-gaps.js` | อยากรู้ผลกระทบของแถวที่ `LOT_ID` ว่าง |


## กฎการนับ (ต้องตรงกับ `eap-server.js`)

สคริปต์พวกนี้ **ก๊อปกฎมาจาก `eap-server.js`** ถ้าแก้กฎที่นั่นต้องแก้ที่นี่ด้วย
ไม่งั้นผลตรวจจะไม่ตรงกับที่หน้าจอแสดงจริง

| กฎ | ทำอะไร |
|---|---|
| `NORM` | ตัดทุกอย่างหลัง `,` หรือ `/` ออกจาก PANEL_ID (`X` กับ `X/0` = แผ่นเดียวกัน) |
| `IS_UNREAD` | แถวที่อ่าน QR ไม่ออก (null / ว่าง / `Error*` / `*NULL*`) |
| `IS_JUNK` | ไม่ใช่แผ่นงาน: `DUMMY*`, jig `M#######A####`, มีอักขระแปลก, สั้นกว่า 10 ตัว |
| `IS_PANEL_EVENT` | ตัด `CEID = 10117` ซึ่งเป็น event ระดับพอร์ต ไม่ใช่การอ่านแผ่น |
| นับ OK | `COUNT(DISTINCT NORM_PANEL)` — นับ **แผ่น** ไม่ใช่ **แถว** |

## สิ่งที่พบจากการตรวจ (2026-08-18)

ตรวจกับข้อมูลจริง 24 ชม. (116,451 แถว / 102 เครื่อง)

**แก้ไปแล้ว**

- แผ่นเดียวถูกบันทึกหลายแถว เพราะเป็นคนละ event — `CEID 10015 / DATAITEM01 = L01` (โหลดเข้า)
  กับ `CEID 10045 / U02` (ปลดออก) บางเครื่องซ้ำ 2-3 เท่า → แก้ด้วย `COUNT(DISTINCT)`
- jig / carrier `M0960002G2000E-0607` และพวก — 2,474 แถว/วัน วิ่งข้าม 14 เครื่อง เคยถูกนับเป็นแผ่นงาน
- `CEID 10117` — 1,648 แถว/วัน บน 15 เครื่อง ไม่มี PANEL_ID เลย เคยถูกนับเป็น "อ่าน QR ไม่ได้" ทำให้ %QR ต่ำเกินจริง
- `Total Sheet` เคยนับรวม 24 ชม. คร่อมหลาย LOT → เปลี่ยนเป็นนับต่อ LOT
  (LOT ที่จบแล้วได้เลขกลม 33% เทียบกับเดิม 5.9% ซึ่งเท่ากับความบังเอิญ)

**ยังแก้ไม่ได้ — เป็นเรื่องข้อมูลต้นทาง ไม่ใช่วิธี query**

- `LOT_ID` ว่าง 35,618 แถว/วัน (30.6%) = แผ่นงานจริง 15,957 แผ่น กระจาย 68 เครื่อง
  ลอง forward-fill แล้วได้ผลดีขึ้นแค่ 21→22 จาก 50 LOT แต่ทำ LOT ที่เดิมถูกพัง 2 ตัว **จึงไม่ใส่**
- เครื่อง plating ใช้ `LOT_ID` เดียวคลุมทั้งวัน — `CPP-Patternplating-01-UL` = 1,079 แผ่น/LOT,
  `CPP-Horizontalplating-01-UL` = 447 → กลุ่มนี้จะไม่ได้ 40/80 ไม่ว่านับยังไง
- LOT เดียวกันแต่คนละสถานีให้เลขไม่ตรง เช่น `LAM-BOP-02` LOT `1260813012000` → `-UL` = 80 แต่ `-L` = 73

สามข้อนี้ควรยกไปคุยกับทีมที่ดูแล EAP
